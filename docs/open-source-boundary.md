# Open Source Boundary

This repository is a public reference implementation for AI-assisted quality gates and risk-based regression recommendation.

The goal is to show the engineering approach, not to publish customer-ready domain intelligence or private delivery assets.

## Open Source

The public repository can include:

- Analyzer pipeline and module structure.
- Public demo rules.
- Sanitized examples.
- Risk scoring interfaces.
- Basic report and PR comment generation.
- Traceability and schema validation foundations.
- Tests and evaluation examples.
- Architecture and roadmap documentation.

## Private Commercial Assets

The following should remain private:

- Production-grade payment, logistics, ad platform, healthcare, and EdTech rule packs.
- Customer-specific adapters for CI, GitHub, OpenAPI, test management, incident, or release systems.
- Historical risk cases, incident patterns, and root-cause analysis knowledge bases.
- Rule weighting strategies and false-positive tuning data.
- Private LLM prompts, eval sets, and scoring rubrics used for paid delivery.
- Deployment scripts, dashboards, and workflow configurations built for specific customers.
- Delivery playbooks, discovery questionnaires, and pricing templates.

## How To Explain This Publicly

Use this sentence in README files, proposals, and project descriptions:

```text
This repository is a public reference implementation. Production-grade rule packs, domain adapters, and customer-specific workflows are delivered in private engagements.
```

## Practical Rule

Public code should prove capability. Private assets should preserve business value.

When in doubt, open-source the framework and keep the domain intelligence private.
